Assumptions Register

The authoritative list of theoretical choices. Every probability in this study is conditional on it.
Important

Everything on this page is a theoretical placeholder pending a cited basis, not an empirical finding. Where an entry still has no source, it says so. If a value is neither data nor a derivation from data, it belongs here, and it does not become a fact by appearing in an equation.

This page is the published index of the register: which assumptions exist, what kind of reasoning each rests on, and how much the answer moves when one is challenged. The authoritative text - each statement written as it is used in code, with its falsification condition and its dependency links - is 03_scenarios/assumptions_register.md in the working repository, which is not public. Where a reader needs the full entry rather than the index row, ask; the register is documentation, not proprietary machinery, and it can be published on this site on request.

Basis is the kind of support: data (constrained by observation), theory (a mechanism we adopt), judgment (a choice we must defend in prose). Confidence is a sensitivity grade, not a truth grade: low means “attack this one first”.

Why so many low grades

How to read the numbers on this page

Two numbers appear next to every probability here, and they mean opposite things. The Wilson interval (about +-0.01 at N = 10,000) measures only sampling noise: it says how precisely this run estimated the share of draws that landed in a scenario region, and it shrinks if we run more draws of the same assumptions - it says nothing about whether those assumptions are right. The sensitivity swing (up to 0.36 at t = 10) measures how far the answer moves when one assumption is moved across the range its own register entry declares: that is structural uncertainty, and it does not shrink with more draws, only with better evidence. So quote the swing, not the interval, when describing uncertainty - a table whose intervals are narrow is a table that has been computed carefully, not a table that is safe to believe. The swings below are one-at-a-time perturbations of the parameters in model_params.yaml, so they do not add up and they do not describe joint moves.

The one-at-a-time run at t = 10 (02_analysis/outputs/sensitivity_t10.csv) reports the largest swings as:

Parameter Largest swing in a scenario share at t = 10
ai_profitability.diffusion_speed (AS-02) 0.36
energy.rebound_coefficient (AS-05) 0.32
thresholds.fiscal_squeeze_trigger (AS-12) 0.28
ai_profitability.diffusion_ceiling (AS-02) 0.25
political_stability.fiscal_sensitivity (AS-08) 0.21
energy.demand_elasticity (AS-06) 0.21

A low confidence grade is therefore not modesty for its own sake: it names the entries whose resolution would actually change the study’s conclusion. Two of the six parameters in the table (AS-05 rebound, AS-06 demand elasticity) are the kind of number that could in principle be measured; the diffusion parameters (AS-02) can only be argued from earlier general-purpose technologies, which is a judgment about historical analogy, not a measurement.

Changing something here

  1. Add or edit the register row first, with a basis and a falsification condition.
  2. Set the value in model_params.yaml, which refuses to load if the register ID is missing.
  3. Record the change in 00_docs/04_changelog.md with the old and new value.
  4. Re-run build_lookup.py; the model_params_hash changes, and with it every probability.

Quoting an old probability after an edit is a citation error, not a rounding difference.
